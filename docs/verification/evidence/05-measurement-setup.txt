Why the ingress controllers had to be separated
  Before, a single controller served every address. A change of host would then
  have been a change in our ingress configuration rather than in the operator's
  DNS -- the proof would have shown that WE can switch, not that HE can.
  152.53.34.232 was withdrawn from controller A and assigned to controller B; no
  name pointed at that address beforehand.

  Established in 03-ingress-separation.txt: the same hostname, addressed to
  controller B, answers 404 with B's default certificate (tls=20), while
  controller A serves it with a valid certificate and 200.

Key handling
  B's key pair was generated with `oydid create` and the public part checked
  against the private one (Oydid.public_key). The private key was taken into the
  secret with --from-file, so that it never passed through the shell history,
  and it lives outside the repository.
