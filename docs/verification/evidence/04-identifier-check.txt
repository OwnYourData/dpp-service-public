  Service        https://dpp-service.ownyourdata.eu   image 260825b
  Operator       did:oyd:zQmX493GLVxE8Wasc8ANTdZmq4YUsvdk5j6Daf7iQaPECt6
  Call           POST /dpp/v1/dpps with the operator's signed token

  In the creation path where the economic operator mints the passport
  identifier itself, the service holds no key for it and cannot alter the DID
  document afterwards; what is wrong at creation stays wrong. The check
  therefore runs before anything is created: does the identifier resolve, and
  does its serviceEndpoint name the host that will actually serve the passport.

  Only the host is compared, never the path. The path carries the
  uniqueProductIdentifier; what is under examination is where a reader is sent.

  Three cases, measured against the running system in the attribute names of
  EN 18223:2026.

  The service cannot revoke what it holds no key for. That is the point of this
  creation path, not an omission -- revocation is the holder's business, and the
  DID document of the deleted passport still carries its serviceEndpoint,
  pointing at a service that now answers 404. An identifier outliving the
  resource it names is the normal condition of a printed carrier.


What this establishes

  Without case 3 nothing would be shown: a check that refused every identifier
  would pass cases 1 and 2 just as well. Only the combination establishes that a
  distinction is being made -- and made on the property that matters, the host a
  reader is sent to.
